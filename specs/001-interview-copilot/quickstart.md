# 快速开始与验证指南 (Quickstart)：智能面试助手

**功能**：[spec.md](./spec.md) ｜ **计划**：[plan.md](./plan.md) ｜ **契约**：[contracts/api-contracts.md](./contracts/api-contracts.md)

本指南用于在实现完成后，**端到端验证**功能是否满足规格。此处只给出运行与验证步骤及预期结果；具体实现细节属于 `tasks.md` 与实现阶段。

---

## 先决条件 (Prerequisites)

- **Python 3.12**（`>=3.12,<3.13`）、Node.js 20 LTS
- 环境变量：`DEEPSEEK_API_KEY`（单一模型全流程所需的 LLM 凭证）
- 已安装依赖：后端 `backend/`（FastAPI 0.115 / Uvicorn / Pydantic 2.9 / SQLModel / **pypdf / python-docx** 等）、前端 `frontend/`（React 18.3 / Vite 5 / Tailwind 3.4 / shadcn-ui）、桌面壳 `electron/`（Electron 32，含悬浮窗）
- 语音识别扩展为可选；未配置时语音按钮禁用，功能不受影响

## 启动 (Setup & Run)

```bash
# 后端（本地 FastAPI）
cd backend && uvicorn src.main:app --host 127.0.0.1 --port 8000

# 前端（开发模式）
cd frontend && npm run dev

# 桌面壳（可选，整合启动）
cd electron && npm run start   # 主进程拉起后端 + 加载前端
```

后端就绪自检：`GET http://127.0.0.1:8000/api/health` 返回 `{ "status": "ok", "model": "deepseek-v4-pro" }`。

## 验证场景 (Validation Scenarios)

> 场景与规格中的验收标准一一对应，可作为冒烟测试脚本。

### 场景 A — 知识库录入与持久化（US3 / FR-001~FR-003, FR-002）
1. 在"知识库管理"页录入档案、1 段实习（含量化成果）、1 个项目（含角色/技术栈/挑战/解决方案/结果）、若干技术栈（含熟练度）。
2. 重启后端后重新打开应用。
3. **预期**：所有录入数据仍存在且可编辑/删除（数据持久化于 `data/copilot.db`）。

### 场景 B — 岗位定制化自我介绍（US1 / FR-004~FR-010, SC-001/004/005）
1. 粘贴一段与用户经历较匹配的 JD，点击"解析岗位"。
2. 点击"生成自我介绍"。
3. **预期**：
   - 首批文字在 2s 内出现（打字机流式，SC-004）；完整生成 < 15s。
   - 输出为三段式：概述核心经历 → 技能总结（含具体项目/数据证据）→ 结合 JD 的业务匹配（SC-001）。
   - 篇幅约 300–400 字（SC-005）。

### 场景 C — 弱匹配角度切换与防穿帮（FR-008/009, SC-002）
1. 换一段与用户经历明显不匹配的 JD，生成自我介绍。
2. **预期**：能力总结自动切换到"学习/个人实践/底层逻辑"角度弥补，**不出现**编造的、与用户无关的工作经历。

### 场景 D — 无 JD 的通用模式降级（FR-006）
1. 不提供 JD 直接生成自我介绍。
2. **预期**：界面提示进入"通用面试模式"，`meta.mode == "generic_fallback"`，仅基于个人经历生成。

### 场景 E — 场景题 STAR 回答（US2 / FR-011~FR-013, SC-003）
1. 输入场景题，例如"如果你负责的项目上线后崩溃了怎么办？"。
2. **预期**：
   - 输出为 STAR 结构，"行动"部分含明确编号步骤（≥3 步，如 1→止损、2→排查、3→修复、4→复盘）。
   - 步骤上下文可追溯到用户某段真实经历（`source_experience_ids` 非空且指向真实记录）。
   - 危机类问题语气沉稳；优化类问题语气进取（语气自适应）。

### 场景 F — 可复现性与流利度（FR-016/019, SC-006/007）
1. 对相同输入连续生成 3 次。
2. **预期**：核心事实（引用经历、数据、匹配点）一致、无自相矛盾；文本无重复啰嗦与明显病句。

### 场景 G — 文档导入知识库（需确认）（US4 / FR-020/021, SC-009/010）
1. 在"个人知识库"页选择"导入文档"，上传一份含文本层的 PDF/DOCX 简历，`usage=parse`。
2. **预期**：
   - 系统在 10 秒内展示"拟新增/修改"的结构化更新建议列表（含冲突标记）。
   - 逐项勾选后点击"确认写入"——**仅被勾选项**写入知识库，未勾选项不写入（无自动覆盖）。

### 场景 H — 附加文档作为素材（US4 / FR-022, FR-023）
1. 在"个人知识库"或"岗位上下文"页选择"附加素材"（`usage=attach`）：知识库用 `scope=profile`，岗位上下文用 `scope=jd`（如公司介绍、岗位补充材料）。
2. **预期**：文档作为素材保留并在后续生成时纳入参考；上传扫描版 PDF（无文本层）时提示失败并建议手工录入或仅附加。

### 场景 I — 悬浮实时辅助与自动滚动（US5 / FR-024~028, SC-011/012/013）
1. 在生成工具栏**先设定流式速率**，将呈现方式切到"悬浮方式"，生成一段回答。
2. **预期**：
   - 回答显示在**无标题栏**的置顶悬浮窗中，可**整体拖动**到屏幕任意位置（3 秒内完成切换与移动）。
   - 调节透明度即时生效，且不低于可读下限。
   - 开启自动滚动后，回答在**生成中与生成后**均以缓慢速度自动滚动，视线可保持在大致固定位置，并可随时**暂停/恢复**。
   - 关闭再次生成时，沿用上次的呈现方式/透明度/位置/速率/自动滚动。

### 场景 J — 多轮对话与会话管理（US6 / FR-029~032, SC-014/015）
1. 在"自我介绍"或"场景题"页生成一段回答；然后在输入框输入追问（如"能把第二点展开一下吗？"）并发送。
2. **预期**：系统基于原回答与会话上下文产生新回答，消息以 Q&A 对话卡片展示。创建第二个会话并切换——每个会话显示独立消息历史。删除会话时确认弹窗拦截。

### 场景 K — 提示词模板管理（US8 / FR-035~039, SC-017）
1. 在左侧导航栏打开"提示词管理"，查看内置模板；编辑并保存 → 系统自动生成副本（copy-on-edit）。
2. **预期**：新模板出现在列表中且可切换生成；切换后回答遵循新模板结构/风格；导出→导入循环生成正确副本。

### 场景 L — 语音输入扩展占位（US7 / FR-033/034, SC-016）
1. 查看输入框旁的麦克风按钮（未配置时不显示或禁用）；在设置中注册一个模拟适配器并启用。
2. **预期**：麦克风变为可用；点击后若适配器就绪，语音转录文本可编辑后再发送。
