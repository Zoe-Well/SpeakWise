# 技术栈智能分类设计

## 目标

将个人知识库中的技术栈从无序标签列表改为稳定的大类分组。新导入的简历直接按固定分类解析；已有技能可通过一次 LLM 调用预览分类结果，用户确认后再保存。

## 固定分类

系统使用稳定的内部键，界面显示对应中文名称：

| 内部键 | 显示名称 | 典型内容 |
| --- | --- | --- |
| `programming_language` | 编程语言 | Java、Python、C++、TypeScript |
| `frontend_client` | 前端与客户端 | React、Electron、Web 与桌面客户端 |
| `backend_data` | 后端与数据 | FastAPI、PostgreSQL、SQLite、向量数据库 |
| `ai_algorithm` | AI 与算法 | PyTorch、计算机视觉、模型训练、算法与数据结构 |
| `agent_llm` | Agent 与 LLM 应用 | Agent、RAG、上下文构建、工具调用、记忆管理 |
| `cloud_devops` | 云平台与 DevOps | Docker、云服务、部署、持续交付 |
| `software_engineering` | 软件工程能力 | 架构、测试、权限、幂等、异常恢复、评估 |
| `other` | 其他 | 无法可靠归入以上类别的技能 |

每项技能只能属于一个主要类别。LLM 返回未知类别或遗漏项目时，结果进入 `other`，不允许创建新类别。

## 新简历导入

复用当前简历解析的 LLM 请求，在解析提示词中提供固定分类及语义说明。返回的每项技能必须携带一个合法分类键，因此不会增加额外的模型调用。导入确认流程保持不变。

## 已有技能整理

技术栈区域增加“AI 智能整理”入口：

1. 前端提交当前简历下全部技能的 ID 和名称。
2. 后端调用 LLM，一次性返回技能 ID 到固定分类键的映射。
3. 后端校验结果，补齐遗漏项并将非法分类改为 `other`，然后只返回预览，不修改数据库。
4. 前端按类别展示预览结果。
5. 用户确认后调用批量应用接口，在一个事务中更新分类；取消则不做任何修改。

没有 API Key、LLM 调用失败或返回无法解析时，显示明确错误并保留原数据。

## 前端展示与手动维护

- 技术栈按固定类别分组展示，只显示包含技能的类别。
- 类别使用标题加技能标签的单层结构，不增加二级分类和折叠状态。
- 原有熟练度和删除操作保持不变。
- 手动添加技能时增加固定类别选择框，默认选择“其他”，用户可以明确指定分类。

## 接口与数据

- 复用现有 `Skill.category` 字段，不增加数据库表或迁移。
- 增加分类预览接口，返回技能 ID、名称、原类别和建议类别。
- 增加批量应用接口，校验技能属于当前激活简历后，在单个事务中更新。
- 对话上下文继续按 `category` 分组，但将内部键转换为中文显示名称，避免提示词中出现技术键名。

## 验证范围

- 简历解析只产生合法固定分类。
- 分类预览不写数据库，确认后才批量保存。
- 取消预览和 LLM 失败均不覆盖现有类别。
- 非法或遗漏的 LLM 分类安全归入“其他”。
- 前端正确分组且隐藏空类别。
- 用户主动添加技能时可选择类别。
- 对话知识库使用中文分类名称。

## 范围限制

本次不实现动态分类、二级分类、拖拽调整、分类增删管理、自动页面加载时调用 LLM，也不修改技能熟练度的解析规则。
